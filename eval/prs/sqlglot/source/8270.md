# PR #8270: fix(snowflake): parse a qualified wildcard in OBJECT_CONSTRUCT_KEEP_NULL

https://github.com/tobymao/sqlglot/pull/8270

## PR body

`OBJECT_CONSTRUCT_KEEP_NULL` is routed to the `JSON_OBJECT` parser. That parser then flows through to `_parse_star()`, only matching an unqualified star.  [Snowflake documents support ](https://docs.snowflake.com/en/sql-reference/functions/object_construct_keep_null#:~:text=When%20invoked%20with%20an%20asterisk%20%28wildcard%29%2C%20the%20OBJECT%20value%20is%20constructed%20from%20the%20specified%20data%20using%20the%20attribute%20names%20as%20keys%20and%20the%20associated%20values%20as%20values%2E%20See%20the%20examples%20below)for the qualified form `OBJECT_CONSTRUCT_KEEP_NULL(tbl.*)`, which raises a `JSONKeyValue` error when parsed today.
 
 
**Fix:** Attempt to match a star column expression in the Snowflake parser before falling back to `_parse_json_object()`. This leaves the base ANSI `_parse_json_object()` as is. 

Closes #8262

## Issue #8262: Snowflake: `OBJECT_CONSTRUCT_KEEP_NULL(t.*)` fails to parse

**Dialect:** read `snowflake`, write `snowflake`.
**Version:** reproduces on `main` (`bac1a89`).

**Disclaimer:** LLMs were used to investigate this issue, write up the script for reproducibility and propose a fix. I verified all findings locally. I've collapsed information into `details` blocks as well to avoid an extremely long issue.


# Summary

Snowflake lets you qualify the wildcard argument of `OBJECT_CONSTRUCT_KEEP_NULL` with a
table name or alias. This is the same behaviour as the `OBJECT_CONSTRUCT()` function, except it builds an `OBJECT` from every column of that row, keeping the `NULL`-valued keys. sqlglot parses the unqualified form but raises on the qualified one:

**Input SQL** (dialect `snowflake`):

```sql
SELECT OBJECT_CONSTRUCT_KEEP_NULL(t.*) FROM tbl AS t
```

**Expected output:** the same SQL back, as `OBJECT_CONSTRUCT(t.*)` already round-trips.

**Actual output + reproduction:**

```python
import sqlglot

# ok
sqlglot.parse_one("SELECT OBJECT_CONSTRUCT(t.*) FROM tbl AS t", read="snowflake").sql(dialect="snowflake")
# 'SELECT OBJECT_CONSTRUCT(t.*) FROM tbl AS t'

# ok
sqlglot.parse_one("SELECT OBJECT_CONSTRUCT_KEEP_NULL(*) FROM tbl AS t", read="snowflake").sql(dialect="snowflake")
# 'SELECT OBJECT_CONSTRUCT_KEEP_NULL(*) FROM tbl AS t'

# ParseError
sqlglot.parse_one("SELECT OBJECT_CONSTRUCT_KEEP_NULL(t.*) FROM tbl AS t", read="snowflake")

>>> sqlglot.errors.ParseError: Required keyword: 'expression' missing for
>>> <class 'sqlglot.expressions.query.JSONKeyValue'>. Line 1, Col: 38.
>>>   SELECT OBJECT_CONSTRUCT_KEEP_NULL(t.*) FROM tbl AS t
```

It isn't specific to a table alias (`OBJECT_CONSTRUCT_KEEP_NULL(tbl.*)` against an unaliased table fails identically), and the `ILIKE` filter form is affected the same way.

| argument | `OBJECT_CONSTRUCT` | `OBJECT_CONSTRUCT_KEEP_NULL` |
| --- | --- | --- |
| `(*)` | `StarMap` | `JSONObject` |
| `(t.*)` | `StarMap` | **ParseError** |
| `(* ILIKE 'col1%')` | `StarMap` | `JSONObject` |
| `(t.* ILIKE 'col1%')` | `StarMap` | **ParseError** |
| `('a', 1)` | `Struct` | `JSONObject` |

# Official Documentation

- [`OBJECT_CONSTRUCT_KEEP_NULL`](https://docs.snowflake.com/en/sql-reference/functions/object_construct_keep_null) regarding the `*` argument: 

> "When you pass a wildcard to the function, you can qualify the  wildcard with the name or alias for the table. For example, to pass in all of the columns  from the table named `mytable`, specify the following: `(mytable.*)`". 

The same section  documents `(* ILIKE 'col1%')` and `(* EXCLUDE col1)`, and notes "Qualifiers are valid when
you use these keywords", with `(mytable.* ILIKE 'col1%')` as the example.

- [`OBJECT_CONSTRUCT`](https://docs.snowflake.com/en/sql-reference/functions/object_construct), which has identical wildcard argument rules. sqlglot already parses this correctly.

# Details

### Root cause

`OBJECT_CONSTRUCT` goes through `build_object_construct`, which handles both unqualified and qualified `*` fine. 

`OBJECT_CONSTRUCT_KEEP_NULL` goes through `_parse_json_object()`, which only handles unqualified `*`, otherwise falling back to key-value pair parsing (`alias.*` is then parsed as a JSON key, but it has no matching value, causing the aforementioned `ParseError`). 

<details>
<summary>Detailed root cause</summary>

`OBJECT_CONSTRUCT` and `OBJECT_CONSTRUCT_KEEP_NULL` are wired up through two different
mechanisms.

`OBJECT_CONSTRUCT` is a `FUNCTIONS` entry ([here](https://github.com/tobymao/sqlglot/blob/bac1a897bb367732792d7d244d9805cc4ad41f0d/sqlglot/parsers/snowflake.py#L564)), and is mapped to [`build_object_construct`.](https://github.com/ishaan-upadhyay/sqlglot/blob/bac1a897bb367732792d7d244d9805cc4ad41f0d/sqlglot/parsers/snowflake.py#L1403). This handles `t.*` as `Column(this=Star(), table=t)` via [`build_var_map` ](https://github.com/tobymao/sqlglot/blob/bac1a897bb367732792d7d244d9805cc4ad41f0d/sqlglot/parser.py#L51) -> [`is_star`](https://github.com/tobymao/sqlglot/blob/bac1a897bb367732792d7d244d9805cc4ad41f0d/sqlglot/parser.py#L51), which handles expressions like `t.*` fine:

```python
class Expression(Expr):

    ...
    @property
    def is_star(self) -> bool:
        return isinstance(self, Star) or (isinstance(self, Column) and isinstance(self.this, Star))
```

`OBJECT_CONSTRUCT_KEEP_NULL` is a `FUNCTION_PARSERS` entry instead, [routed to the SQL
standard `JSON_OBJECT` grammar](https://github.com/tobymao/sqlglot/blob/bac1a897bb367732792d7d244d9805cc4ad41f0d/sqlglot/parsers/snowflake.py#L740) via `_parse_json_object` (it was added that way in #2769, for #2768):

and `_parse_json_object` recognises only an *unqualified* star:

```python
# sqlglot/parser.py
def _parse_json_object(self, agg=False):
    star = self._parse_star()
    expressions = (
        [star]
        if star
        else self._parse_csv(lambda: self._parse_format_json(self._parse_json_key_value()))
    )
```

[`_parse_star()` matches a bare `TokenType.STAR` token. ](https://github.com/ishaan-upadhyay/sqlglot/blob/bac1a897bb367732792d7d244d9805cc4ad41f0d/sqlglot/parser.py#L8903)

```python
    def _parse_star(self) -> exp.Expr | None:
        if self._match(TokenType.STAR):
            return self.PRIMARY_PARSERS[TokenType.STAR](self, self._prev)
        return self._parse_placeholder()
```

On `t.*` the current token is an identifier, so parsing falls through to `_parse_json_key_value()`, which takes `t.*` as the key, finds no `:` or `,` separator, and builds a `JSONKeyValue` with no `expression`,  hence the "Required keyword" error.
</details>


### Possible fix
<details>
<summary>Details</summary>

Give the Snowflake function its own handler that matches a qualified star before falling back to the `JSON_OBJECT` grammar, leaving the ANSI `JSON_OBJECT` path untouched:

```python
     FUNCTION_PARSERS = {
         **parser.Parser.FUNCTION_PARSERS,
         "DATE_PART": lambda self: self._parse_date_part(),
         "DIRECTORY": lambda self: self._parse_directory(),
-        "OBJECT_CONSTRUCT_KEEP_NULL": lambda self: self._parse_json_object(),
+        "OBJECT_CONSTRUCT_KEEP_NULL": lambda self: self._parse_object_construct_keep_null(),
         "LISTAGG": lambda self: self._parse_string_agg(),
```

```python
    def _parse_object_construct_keep_null(self) -> exp.Expr:
        # OBJECT_CONSTRUCT_KEEP_NULL(tbl.*) is valid Snowflake, as is OBJECT_CONSTRUCT(tbl.*).
        # _parse_json_object() only recognises an unqualified star, so match the
        # qualified form here before falling back to the JSON_OBJECT grammar.
        index = self._index
        column = self._parse_column()
        if column is not None and column.is_star:
            return self.expression(exp.JSONObject(expressions=[column]))

        self._retreat(index)
        return self._parse_json_object()
```

Going through `_parse_column()` also continues to allow the `ILIKE` + unqualified `*` forms. `Expression.is_star` already handles `Star()` as well as `Column(this=Star())`. The generator needs no change:

`exp.JSONObject: lambda self, e: self.func("OBJECT_CONSTRUCT_KEEP_NULL", *e.expressions)` renders the column back as `t.*`.

I ran the test suite on `main` with this change: **1238 passed, 19360 subtests passed**, identical to the unpatched suite at the same commit. 
</details>

I would be happy to submit a PR if this approach makes sense, with a `test_snowflake.py` case alongside the existing `OBJECT_CONSTRUCT` ones.


### Fully reproducible code snippet

The script below installs sqlglot from `main` and monkey-patches in the proposed fix to
demonstrate viability.

<details>
<summary>Script for reproduction + output</summary>

```python
#!/usr/bin/env -S SETUPTOOLS_SCM_PRETEND_VERSION=0 uv run --script
# /// script
# requires-python = ">=3.11"
# dependencies = [
#   "sqlglot @ https://github.com/tobymao/sqlglot/archive/refs/heads/main.tar.gz",
# ]
# ///
"""Repro: OBJECT_CONSTRUCT_KEEP_NULL(tbl.*) fails to parse in the snowflake dialect.

Runs against main. Every case is parsed with read="snowflake" and written back
with dialect="snowflake"; "ok" means the output matched the input exactly.

Installing from the main tarball rather than git+ because the repo has a private
submodule (sqlglot-integration-tests), which makes a recursive clone fail. The
tarball carries no git metadata, hence SETUPTOOLS_SCM_PRETEND_VERSION above.

Only the qualified star on the KEEP_NULL variant is affected. The unqualified
star parses, with or without ILIKE, and OBJECT_CONSTRUCT parses in every form.

Expected output:

    current
       ok    OBJECT_CONSTRUCT(*)                           StarMap
       ok    OBJECT_CONSTRUCT(t.*)                         StarMap
       ok    OBJECT_CONSTRUCT(t.* ILIKE 'col1%')           StarMap
       ok    OBJECT_CONSTRUCT_KEEP_NULL(*)                 JSONObject
       ok    OBJECT_CONSTRUCT_KEEP_NULL(* ILIKE 'col1%')   JSONObject
       ok    OBJECT_CONSTRUCT_KEEP_NULL('a', 1)            JSONObject
       FAIL  OBJECT_CONSTRUCT_KEEP_NULL(t.*)               ParseError: Required keyword: 'expression' missing ...
       FAIL  OBJECT_CONSTRUCT_KEEP_NULL(t.* ILIKE 'col1%') ParseError: Required keyword: 'expression' missing ...

    with the proposed fix
       ... the same, with both FAILs now ok and JSONObject
"""

import sqlglot
from sqlglot import exp
from sqlglot.dialects.snowflake import Snowflake

CASES = [
    "SELECT OBJECT_CONSTRUCT(*) FROM tbl AS t",
    "SELECT OBJECT_CONSTRUCT(t.*) FROM tbl AS t",
    "SELECT OBJECT_CONSTRUCT(t.* ILIKE 'col1%') FROM tbl AS t",
    "SELECT OBJECT_CONSTRUCT_KEEP_NULL(*) FROM tbl AS t",
    "SELECT OBJECT_CONSTRUCT_KEEP_NULL(* ILIKE 'col1%') FROM tbl AS t",
    "SELECT OBJECT_CONSTRUCT_KEEP_NULL('a', 1) FROM tbl AS t",
    "SELECT OBJECT_CONSTRUCT_KEEP_NULL(t.*) FROM tbl AS t",
    "SELECT OBJECT_CONSTRUCT_KEEP_NULL(t.* ILIKE 'col1%') FROM tbl AS t",
]

# ---------------------------------------------------------------- proposed fix


def parse_object_construct_keep_null(self) -> exp.Expr:
    """Match a qualified star before falling back to the JSON_OBJECT grammar.

    Upstream this is a SnowflakeParser method, wired into FUNCTION_PARSERS in
    place of the current `lambda self: self._parse_json_object()`.
    """
    index = self._index
    column = self._parse_column()
    if column is not None and column.is_star:
        return self.expression(exp.JSONObject(expressions=[column]))

    self._retreat(index)
    return self._parse_json_object()


# --------------------------------------------------------------------- harness


def label(sql: str) -> str:
    return sql[len("SELECT ") : -len(" FROM tbl AS t")]


def report() -> None:
    for sql in CASES:
        try:
            ast = sqlglot.parse_one(sql, read="snowflake")
        except sqlglot.errors.ParseError as e:
            print(f"   FAIL  {label(sql):<45} ParseError: {str(e).splitlines()[0]}")
            continue

        written = ast.sql(dialect="snowflake")
        node = type(ast.selects[0]).__name__
        if written == sql:
            print(f"   ok    {label(sql):<45} {node}")
        else:
            print(f"   DIFF  {label(sql):<45} {node}, wrote back {label(written)}")


print("current")
report()

# The parser looks FUNCTION_PARSERS up on the class at parse time, so replacing
# the entry is enough to swap the handler.
Snowflake.Parser.FUNCTION_PARSERS["OBJECT_CONSTRUCT_KEEP_NULL"] = parse_object_construct_keep_null

print("\nwith the proposed fix")
report()
```
