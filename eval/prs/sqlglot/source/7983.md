## Issue #7958: Correlated subquery unnesting collapses negated correlation predicates

**Before you file an issue**

- The defect is reproduced on current `main` commit `33de21fc21cdc05755a2de39318b292c10ccec0f`.
- The relevant path is SQLGlot's dialect-independent optimizer and Python executor, so separate read and write dialect settings do not apply.
- Open and closed issue, pull-request, source-history, and release searches found no exact duplicate.

**Fully reproducible code snippet**

```python
from sqlglot.executor import execute

tables = {x: [{id: 1}, {id: 2}, {id: 3}], y: [{id: 1}, {id: 2}]}
sql = "
SELECT x.id FROM x AS x
WHERE EXISTS (SELECT 1 FROM y AS y WHERE NOT (y.id = x.id))
"
print(execute(sql, tables=tables).rows)
```

The result is empty. SQL semantics require IDs 1, 2, and 3 because each `x` row has at least one unequal `y` row. Replacing the inner predicate with the positive equality `y.id = x.id` is a control and correctly returns IDs 1 and 2. The optimized affected plan contains `WHERE FALSE`.

**Expected behavior**

Decorrelation must preserve the polarity and truth value of correlated predicates.

**Root cause**

`decorrelate` extracts the correlated comparison without preserving a direct enclosing `NOT`. It then replaces the inner comparison with `TRUE`, so `NOT (y.id = x.id)` collapses to `NOT (TRUE)`.

**Proposed correction**

Normalize a directly negated comparison to its complementary comparison before decorrelation. When there is no positive equality join key, aggregate the inner comparison key, join that aggregate on `TRUE`, and evaluate the preserved comparison with `ARRAY_ANY`.

**Validation**

The isolated local correction passes focused optimizer and executor regressions, positive and `NOT EXISTS` controls, `NULL`/empty-input adversarial cases, the full executor suite, the relevant optimizer fixture, Ruff, mypy, and `git diff --check`.
