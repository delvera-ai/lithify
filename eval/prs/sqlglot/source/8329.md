# PR #8329: fix(expressions): render a DynamicIdentifier in Table.name [CLAUDE]

https://github.com/tobymao/sqlglot/pull/8329

## PR body

Fixes #8328.

`Table.name` returns `''` for a table named by `IDENTIFIER()`, because it short-circuits on `isinstance(self.this, Func)` and `DynamicIdentifier` is declared `Expression, Func`. That guard is right for table-valued functions like `read_csv()`, but it predates `DynamicIdentifier` by three years and the PRs that added that node only touch generation, so catching it looks accidental rather than intended.

This returns the bare name, matching `Placeholder` and `Parameter` — `'p'` for `:p`, `'v'` for `@v`, with `.sql()` keeping the sigil. It also fixes two knock-on effects described in the issue: `qualify()` no longer gives two unaliased dynamic tables indistinguishable positional aliases, and `exp.table_name()` stops logging an unsupported-argument warning and returning the raw call text.

`read_csv()` and `generate_series()` still return `''`, so the carve-out doesn't reach real table-valued functions. `SKIP_INTEGRATION=1 python -m unittest` is `OK (skipped=48)` at 1354 tests with and without the change; the added assertions fail with `'' != 'tbl'` if the fix is reverted.

I left `Table.db` and `Table.catalog` alone. They are also empty for a dynamic identifier in a qualifier position, but they go through `text()`, which documents itself as handling only strings and leaf expressions, and every `IDENTIFIER()` shape in the test suite puts it in a whole-object position — so I did not want to assume the qualifier form is supported.

*Disclosure: I used Claude to investigate this and draft the patch. I verified the reproduction, root cause and test results myself.*


## Issue #8328: Table.name is empty for a table named by IDENTIFIER()

`Table.name` returns an empty string when a table's name is an `IDENTIFIER()` call, even though the name is present in the tree and generates correctly.

```python
>>> import sqlglot
>>> t = sqlglot.parse_one("SELECT * FROM IDENTIFIER(:tbl)", dialect="snowflake").find(sqlglot.exp.Table)
>>> t.name
''
>>> t.this
DynamicIdentifier(this=Placeholder(this=tbl))
>>> t.sql(dialect="snowflake")
'IDENTIFIER(:tbl)'
```

Expected `'tbl'`, consistent with `Placeholder.name == 'p'` for `:p` and `Parameter.name == 'v'` for `@v` — the bare name, with `.sql()` keeping the sigil.

**Why this looks like an oversight rather than intent.** `Table.name` short-circuits on `isinstance(self.this, Func)`:

```python
# sqlglot/expressions/query.py
@property
def name(self) -> str:
    if not self.this or isinstance(self.this, Func):
        return ""
    return self.this.name
```

That guard is correct for table-valued functions like `generate_series()` or `read_csv()`, where the function name is not a table name. It was added in 756181771 (June 2023). `DynamicIdentifier` was introduced three years later (#7723, #7796) as `class DynamicIdentifier(Expression, Func)`, so it inherits the guard by accident. Both of those PRs are scoped to generation; neither touches `.name`.

**It has knock-on effects beyond the accessor.** Two unaliased dynamic tables become indistinguishable after `qualify()`:

```python
>>> from sqlglot.optimizer.qualify import qualify
>>> q = qualify(sqlglot.parse_one("SELECT * FROM IDENTIFIER(:a), IDENTIFIER(:b)", dialect="snowflake"), dialect="snowflake")
>>> [t.alias for t in q.find_all(sqlglot.exp.Table)]
['_0', '_2']
```

and `exp.table_name()` falls back to the raw call text while logging `IDENTIFIER() with non-literal arguments is not supported`:

```python
>>> sqlglot.exp.table_name(t)
'IDENTIFIER(:tbl)'
```

Both resolve once `.name` works.

**Fix.** A `name` property on `DynamicIdentifier` delegating to `self.this`, plus an isinstance check ahead of the `Func` guard in `Table.name`. Seven lines across `expressions/core.py` and `expressions/query.py`. On `0714112aa`, `SKIP_INTEGRATION=1 python -m unittest` gives `Ran 1354 tests ... OK (skipped=48)` both with and without the change, and `tests/dialects/test_snowflake.py` is 99/99. I checked that `read_csv()` and `generate_series()` still return `''`, so the carve-out doesn't leak to real table-valued functions. Handles `:tbl`, `$tbl`, `$1` and `'literal'` payloads.

**Deliberately out of scope:** `Table.db` and `Table.catalog` are also empty when the dynamic identifier sits in a qualifier position (`db.IDENTIFIER(:sch).tbl`). Those go through `text()`, which documents itself as only handling strings and leaf expressions, and every `IDENTIFIER()` shape in the test suite puts it in a whole-object position, so I've left that alone rather than assume the qualifier form is supported.

Happy to open the PR if you'd prefer that to a core-team fix.
