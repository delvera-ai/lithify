# PR #8233: Fix(postgres): don't emit JSON_EXTRACT_PATH with no keys for a root-only JSON path [CLAUDE]

https://github.com/tobymao/sqlglot/pull/8233

## PR body

Fixes #8232.

A root-only JSON path (`$`) has no key segments, so the Postgres generator produced `JSON_EXTRACT_PATH` / `JSON_EXTRACT_PATH_TEXT` with **no path arguments**, which PostgreSQL rejects (there is no zero-key overload):

```python
sqlglot.transpile("SELECT json_extract(a, '$') FROM t", read="mysql", write="postgres")
# before: SELECT JSON_EXTRACT_PATH(a) FROM t   -- invalid in Postgres
# after:  SELECT a #> '{}' FROM t
```

In `generators/postgres.py`, `_json_extract_sql` builds the `JSON_EXTRACT_PATH(...)` call from the path's key segments. For a root-only path the segment list is empty, so the call is emitted with just the column and no keys.

The fix detects a root-only `JSONPath` (all parts are `JSONPathRoot`) and emits the path operator with an empty path array instead — `a #> '{}'` for `JSONExtract` (`->`) and `a #>> '{}'` for `JSONExtractScalar` (`->>`), matching what the reporter expected. Keyed paths (`$.k`, `$.k.n`) take the existing code path and are unchanged.

Added two `validate_all` cases in `tests/dialects/test_postgres.py` (root `->` and `->>`); both fail on `main` and pass with this change. Full `test_postgres.py` suite is green.

## Issue #8232: Postgres: a root-only JSON path (`$`) generates JSON_EXTRACT_PATH with no path arguments, which PostgreSQL rejects

- Read dialect: `postgres` (any read dialect that yields a root-only `JSONPath`)
- Write dialect: `postgres`
- Still reproduces on `main` at `05eed63b2`

A root-only JSON path (`$`) is generated as `JSON_EXTRACT_PATH` / `JSON_EXTRACT_PATH_TEXT` with no path arguments. PostgreSQL has no such overload, so the statement is rejected.

```
input:    SELECT json_extract(a, '$') FROM t
emitted:  SELECT JSON_EXTRACT_PATH(a) FROM t
expected: SELECT a #> '{}' FROM t
```

**Fully reproducible code snippet**

```python
import sqlglot

for sql in ["SELECT json_extract(a, '$') FROM t", "SELECT json_extract_scalar(a, '$') FROM t"]:
    print(sqlglot.parse_one(sql, read="postgres").sql(dialect="postgres"))
```

```
SELECT JSON_EXTRACT_PATH(a) FROM t
SELECT JSON_EXTRACT_PATH_TEXT(a) FROM t
```

A path with one key is generated correctly, which isolates the root-only case:

```python
import sqlglot

print(sqlglot.parse_one("SELECT json_extract(a, '$.k') FROM t", read="postgres").sql(dialect="postgres"))
# SELECT JSON_EXTRACT_PATH(a, 'k') FROM t
```

**On PostgreSQL 17.10**

`json_extract_path` is declared `json_extract_path(from_json json, VARIADIC path_elems text[])`, and no overload matches a lone `json` argument:

| statement | result |
|---|---|
| `json_extract_path('{"a":1}'::json)` — emitted | `ERROR: function json_extract_path(json) does not exist` |
| `json_extract_path_text('{"a":1}'::json)` — emitted | `ERROR: function json_extract_path_text(json) does not exist` |
| `'{"a":1}'::json #> '{}'` | `{"a":1}` |
| `'{"a":1}'::json #>> '{}'` | `{"a":1}` |

`#> '{}'` and `#>> '{}'` take an empty path array and return the whole document, which is what a root-only path means. (`json_extract_path(x, VARIADIC ARRAY[]::text[])` also works, but that is not what is emitted.)

Note `a -> '$'` is not an alternative spelling — on PostgreSQL that looks up a key literally named `$`.

Round-tripping does not surface this: `JSON_EXTRACT_PATH(a)` re-parses cleanly as an anonymous function call, so the tree survives `parse -> generate -> parse` and only the server rejects it.

**Where it comes from**

`json_extract_segments` (`sqlglot/dialects/dialect.py:2268`) builds the argument list by skipping path parts that render empty:

```python
segments = []
for segment in path.expressions:
    escape = segment.args.get("quoted")
    path = self.sql(segment)
    if path:                       # JSONPathRoot renders as "", so it is skipped
        ...
        segments.append(path)
...
return self.func(name, expression.this, *segments)
```

`JSONPathRoot` renders as the empty string, so for `$` nothing is appended, `segments` is empty, and the function is emitted with only its first argument. Postgres reaches this via `_json_extract_sql` (`sqlglot/generators/postgres.py:183`). Dialects that keep the path as a single string literal argument are unaffected — sqlite, mysql, duckdb, presto, trino, bigquery, hive, spark and databricks all keep `$` intact.

A possible fix is to emit `#> '{}'` for `JSONExtract` and `#>> '{}'` for `JSONExtractScalar` when the path is root-only. The scalar form needs the operator rather than a cast, since `'"x"'::json #>> '{}'` returns `x` while `('"x"'::json)::text` returns `"x"`.

**Official Documentation**

- PostgreSQL [JSON Functions and Operators](https://www.postgresql.org/docs/current/functions-json.html) — `json_extract_path(from_json json, VARIADIC path_elems text[])`, and the `#>` / `#>>` path operators.
