# PR #7929: Feat(mysql): support INSERT ... SET ... syntax

https://github.com/tobymao/sqlglot/pull/7929

## PR body

Closes #7927

MySQL's `INSERT ... SET` form is documented as equivalent to the standard column-list form, so we normalize it at parse time into the canonical `Schema` + `Values` AST rather than introducing a new representation. Besides preserving semantics, this also easily enables transpilation towards other dialects. Column qualifiers on assignment targets (`SET t.a = 1`) are dropped since MySQL only accepts qualifiers that resolve to the single insert target, making them redundant.


## Issue #7927: [MySQL] INSERT … SET is not supported

This primarily applies to the `read` part of the `mysql` dialect. At this time, sqlglot uses a generic `INSERT` parser in its MySQL dialect.

**Fully reproducible code snippet**
```
sqlglot.parse_one("INSERT INTO `test_table` SET `test_col_1` = 123, `test_col_2` = '456'", dialect="mysql")
```

Results in:
```
sqlglot.errors.ParseError: Invalid expression / Unexpected token. Line 1, Col: 28.
  INSERT INTO `test_table` SET `test_col_1` = 123, `test_col_2` = '456'
```
(`SET` is indicated as an unknown token)

**Official Documentation**
https://dev.mysql.com/doc/refman/8.4/en/insert.html
https://dev.mysql.com/doc/refman/8.0/en/insert.html
https://dev.mysql.com/doc/refman/5.7/en/insert.html

More specifically (quoted from 8.4),
> **INSERT** [LOW_PRIORITY | DELAYED | HIGH_PRIORITY] [IGNORE]
>    [INTO] tbl_name
>    [PARTITION (partition_name [, partition_name] ...)]
>    **SET** assignment_list
>    [AS row_alias[(col_alias [, col_alias] ...)]]
>    [ON DUPLICATE KEY UPDATE assignment_list]
