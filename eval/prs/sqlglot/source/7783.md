# PR #7783: fix(snowflake): preserve `PATTERN` clause on staged files without `FILE_FORMAT`

https://github.com/tobymao/sqlglot/pull/7783

## PR body

## Summary

Closes https://github.com/tobymao/sqlglot/issues/7782

Currently in `Generator.table_sql`, the `PATTERN` clause is only emitted inside the `if file_format:` block, so whenever `FILE_FORMAT` is absent the pattern is never rendered. 

This PR aims to fix this by performing a `pattern` lookup out of the `if file_format:` block and adds a check so that pattern-only stage references are rendered correctly. Also added a test to cover the use-case and behavior.

Open to guidance and feedback 😄 

## Issue #7782: Snowflake: `PATTERN` clause is dropped when staged file has no `FILE_FORMAT`

**Fully reproducible code snippet**

When reading from a Snowflake stage with a `PATTERN` but no `FILE_FORMAT`, the `PATTERN => ...` clause is silently dropped on output:

```
sql = "SELECT * FROM @mystage (PATTERN => '.*data-100.*')"
print(sqlglot.parse_one(sql, dialect="snowflake").sql(dialect="snowflake"))
```
Actual output:

```
SELECT * FROM @mystage
```

Expected output:

```
SELECT * FROM @mystage (PATTERN => '.*data-100.*')
```

**Official Documentation**

According to: https://docs.snowflake.com/en/user-guide/querying-stage#optional-parameters
both `FILE_FORMAT` and `PATTERN` are optional parameters and can be passed separately from each other.
