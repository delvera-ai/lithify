# PR #7778: fix(presto): transpile FROM_ISO8601_DATE to cast

https://github.com/tobymao/sqlglot/pull/7778

## PR body

Fixes #7777

`FROM_ISO8601_DATE` is a Presto/Trino function that parses an ISO 8601 string into a date. It wasn't recognized as a dedicated expression, so it parsed as `Anonymous` and passed through verbatim to every dialect:

```python
>>> sqlglot.parse_one("SELECT FROM_ISO8601_DATE('2020-05-11')", "trino").sql("snowflake")
"SELECT FROM_ISO8601_DATE('2020-05-11')"   # before — invalid outside Presto/Trino
"SELECT CAST('2020-05-11' AS DATE)"        # after
```

### Change
- Add a dedicated `exp.FromISO8601Date` expression.
- Transpile it to `CAST(... AS DATE)` in the base `Generator`, so all dialects handle it (Snowflake, Spark, BigQuery, DuckDB, …).
- Add an explicit `exp.FromISO8601Date` transform to the Presto generator so Presto/Trino keep emitting the native function.

This mirrors the `from_iso8601_timestamp` fix in #7776.

## Issue #7777: from_iso8601_date is not correctly transpiled from Trino to other dialects

Similar to #7775, the Trino [`from_iso8601_date`](https://trino.io/docs/current/functions/datetime.html#from_iso8601_date) function is not transpiled to other dialects. It isn't even recognized as a dedicated expression — it parses as `Anonymous` and passes through verbatim to every dialect:

```python
>>> import sqlglot
>>> p = sqlglot.parse_one("SELECT FROM_ISO8601_DATE('2020-05-11')", "trino")
>>> repr(p)
Select(
  expressions=[
    Anonymous(
      this=FROM_ISO8601_DATE,
      expressions=[
        Literal(this='2020-05-11', is_string=True)])])
>>> for d in ["snowflake", "duckdb", "spark", "bigquery"]:
...     print(d, "->", p.sql(d))
snowflake -> SELECT FROM_ISO8601_DATE('2020-05-11')
duckdb   -> SELECT FROM_ISO8601_DATE('2020-05-11')
spark    -> SELECT FROM_ISO8601_DATE('2020-05-11')
bigquery -> SELECT FROM_ISO8601_DATE('2020-05-11')
```

`FROM_ISO8601_DATE` only exists in Presto/Trino. For other dialects it should be transpiled to a `CAST(... AS DATE)`, e.g.:

```sql
-- snowflake/duckdb/spark/bigquery
SELECT CAST('2020-05-11' AS DATE)
```

This mirrors the `from_iso8601_timestamp` fix in #7775 / #7776.
