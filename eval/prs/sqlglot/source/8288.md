# PR #8288: fix(spark): distinguish GROUPING SETS suffix syntax

https://github.com/tobymao/sqlglot/pull/8288

## PR body

Hive and Spark support a non-standard form of `GROUP BY` and `GROUPING SETS`, where no comma separates ordinary grouping expressions from `GROUPING SETS` clauses.

Currently, sqlglot incorrectly adds a comma to the no comma form - this PR fixes that.

### Semantics
The semantics differ between the comma and comma-less forms:
 - No comma: `GROUP BY a, b, c GROUPING SETS ((a), (a, b))`
   - GROUPING SETS determines the effective grouping sets: this example produces (a) and (a, b).
   - If selected, `c` is present in the output and NULL in every aggregate row.
 - Comma: `GROUP BY a, b, c, GROUPING SETS ((a), (a, b))`
   - Ordinary grouping expressions are combined with each grouping set using cross-product semantics.
   - In this example, `a`, `b`, and `c` are included in every resulting grouping set. 

### Engine support

- No comma form
  - Hive, Spark, and Databricks support
  - Other engines do not
- Comma form 
  - Hive, Spark 3.1.x, and Clickhouse do NOT support
  - Spark 3.2 and other engines DO support

Closes #8266

# Spark/Hive: GROUP BY … GROUPING SETS round-trip inserts comma and loses Hive-compat form

## Description

For Spark/Hive SQL, these two `GROUP BY` forms are both valid, but they are not the same construct and can differ semantically:

```sql
-- A) Hive-compat (no comma before GROUPING SETS)
-- See Spark docs: "For Hive compatibility Spark allows GROUP BY ... GROUPING SETS (...)"
SELECT count(1), d, h
FROM t
GROUP BY d, h
GROUPING SETS ((d, h), (d));

-- B) Mixed grouping analytics (comma before GROUPING SETS)
-- See Spark docs: GROUP BY { expr | GROUPING SETS (...) | CUBE (...) | ROLLUP (...) } [, ...]
SELECT count(1), d, h
FROM t
GROUP BY d, h, GROUPING SETS ((d, h), (d));
```

References:

- https://spark.apache.org/docs/latest/sql-ref-syntax-qry-select-groupby.html
- Related discussion: https://github.com/tobymao/sqlglot/issues/3361
- Related discussion: https://github.com/tobymao/sqlglot/issues/3410

## Problem

sqlglot:

1. Parses **A** and **B** into the **same** `Group` AST shape:

   ```text
   Group(
     expressions=[d, h],
     grouping_sets=[GroupingSets(...)]
   )
   ```

2. Does **not** record whether the original SQL used a comma or whitespace before `GROUPING SETS`.

3. On generate, `group_sql` joins grouping columns and `GROUPING SETS` with `GROUPINGS_SEP=','`.

So a Hive-compat input (A) round-trips to the comma form (B). That can change Spark semantics and/or break engines/tools that expect the Hive-compat spelling.

## Fully reproducible code snippet

```python
from sqlglot import parse_one

sql_hive = (
    "SELECT count(1), d, h FROM t "
    "GROUP BY d, h GROUPING SETS ((d, h), (d))"
)
sql_mixed = (
    "SELECT count(1), d, h FROM t "
    "GROUP BY d, h, GROUPING SETS ((d, h), (d))"
)

ast_hive = parse_one(sql_hive, dialect="spark")
ast_mixed = parse_one(sql_mixed, dialect="spark")

print(ast_hive)
print(ast_mixed)
print(ast_hive == ast_mixed)  # True — separator style is lost

print(ast_hive.sql(dialect="spark"))
# SELECT COUNT(1), d, h FROM t GROUP BY d, h, GROUPING SETS ((d, h), (d))
#                                                          ^ inserted comma

print(ast_mixed.sql(dialect="spark"))
# SELECT COUNT(1), d, h FROM t GROUP BY d, h, GROUPING SETS ((d, h), (d))
```

Also reproduces with `pretty=True`.

## Expected behavior

Round-trip should preserve the original separator style (Hive-compat whitespace vs mixed-analytics comma), **or** the AST should distinguish the two forms so dialects can emit the correct Spark/Hive SQL.

At minimum for `dialect="spark"` / `"hive"`:

```python
parse_one(sql_hive, dialect="spark").sql(dialect="spark")
# should keep: GROUP BY d, h GROUPING SETS (...)
# not become:  GROUP BY d, h, GROUPING SETS (...)
```

## Actual behavior

Both inputs collapse to the comma form on generate.

## Package version

- sqlglot **25.32.0** (reproduced)
- sqlglot **30.17.0** (reproduced; `GROUPINGS_SEP` is still `","`, same `group_sql` behavior)

## Notes / possible directions

- Today `WITH CUBE` / `WITH ROLLUP` already avoid inserting a comma in some paths; `GROUPING SETS` does not get equivalent treatment for the Hive-compat form.
- A robust fix likely needs parse-time recording of the separator (or distinct AST representation), not only changing the default `GROUPINGS_SEP`, because both forms are valid in Spark and must remain distinguishable.
