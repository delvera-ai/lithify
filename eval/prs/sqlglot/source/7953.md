## PR body

Fixes #7952.

The Python executor previously filtered join candidates after constructing the join result. That loses preserved-side rows when a complete `ON` condition rejects a candidate, and it cannot synthesize both sides of a FULL JOIN.

This change evaluates the complete `ON` condition while constructing hash and nested-loop joins, tracks matched row indexes, and appends the required null-extended rows for LEFT, RIGHT, and FULL joins. One reusable condition context avoids per-pair setup cost.

Tests cover a disjoint FULL JOIN, a LEFT JOIN with a rejecting residual predicate, and nearby valid non-equi inner-join behavior.

## Issue #7952: Python executor outer joins lose required null-extended rows

**Before you file an issue**

- The defect is reproduced on current `main` commit `33de21fc21cdc05755a2de39318b292c10ccec0f`.
- The relevant path is SQLGlot's dialect-independent optimizer, parser, or
  Python executor, so separate read and write dialect settings do not apply.
- Open and closed issue, pull-request, source-history, and release searches
  found no exact duplicate.

**Fully reproducible code snippet**

```python
from sqlglot.executor import execute

tables = {"x": [{"id": 1}], "y": [{"id": 2}]}
sql = "SELECT x.id, y.id FROM x FULL OUTER JOIN y ON x.id = y.id"
print(execute(sql, tables=tables).rows)
```

The result is empty. A FULL OUTER JOIN with disjoint keys requires two rows:
`(1, NULL)` and `(NULL, 2)`. A disjoint LEFT JOIN is a control. A LEFT JOIN
whose candidate key match fails a residual `ON` predicate also loses the
required null-extended left row.

**Expected behavior**

Every unmatched preserved-side row requires one null-extended output row.

**Root cause**

Join code does not track complete-ON matches or synthesize all required unmatched rows.

**Proposed correction**

Evaluate complete ON conditions while tracking matches and append null-extended rows by side.

**Validation**

The isolated correction has a positive regression, a nearby
negative/adversarial control, and passing executor and broader unit suites.
