Optimizer / BigQuery: in BigQuery's `GROUP BY`, `HAVING` and `QUALIFY` clauses, projection aliases share a namespace with source names, and on a collision the alias captures the qualifier. With a projection `ARRAY_AGG(b) AS agg` and a source named `agg`, a reference `agg.a` resolves to the projection and then fails ("Column agg contains an aggregation function"), while the bare name `a` resolves to the source column. `qualify` works around this by replacing such a column with its bare identifier, which breaks later optimizer passes. Represent these shadowed clause references as qualified columns instead, so qualification, pushdown and transpilation from BigQuery stay correct. (Stated requirement: such a reference is an `exp.Column` whose `table` is the source name, with a `shadow` argument set to true.)
