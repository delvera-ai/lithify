Parsing malformed numbers can crash with a raw `decimal.InvalidOperation` instead of a sqlglot error:

```python
import sqlglot
sqlglot.parse_one("SELECT .1.2", dialect="oracle")
# decimal.InvalidOperation: [<class 'decimal.ConversionSyntax'>]
```

Bad numeric inputs must not leak `decimal.InvalidOperation`: converting such a literal to a Python value must fail gracefully, so parsing produces a normal result or a sqlglot `ParseError`.
