## Issue #7462: BigQuery parser fails on MODEL-first AI or ML GENERATE function signatures

`AI/ML.GENERATE*` `MODEL`-first function syntax in BigQuery currently fails with parser errors when using the documented signatures.

The issue is reproducible on the latest `main` branch of SQLGlot (verified at commit `2367eeb3`).

### Minimal reproducible example:

```python
from sqlglot import parse_one

sql = "SELECT * FROM ML.GENERATE_TEXT(MODEL `mydataset.gemini_model`, TABLE `mydataset.prompt_table`, STRUCT(0.15 AS temperature))"
parse_one(sql, dialect="bigquery")
```

### Actual behavior:
Raises:

```text
sqlglot.errors.ParseError: Expecting ). Line 1, Col: 61.
  SELECT * FROM ML.GENERATE_TEXT(MODEL `mydataset.gemini_model`, TABLE `mydataset.prompt_table`, STRUCT(0.15 AS temperature))
```

### Expected behavior:
The query should parse successfully in BigQuery dialect and round-trip back to equivalent SQL.

### Additional affected signatures (same failure pattern):
- `AI.GENERATE_TEXT(MODEL ..., TABLE ..., STRUCT(...))`
- `AI.GENERATE_TABLE(MODEL ..., (SELECT ...), STRUCT(...))`
- `AI.GENERATE_BOOL(MODEL ..., ...)`
- (likely same parser-path impact on related `AI.GENERATE_*` model-first forms)
