In sqlglot (clickhouse dialect): Generate MODIFY COLUMN for column type changes.

## Issue #7793: ClickHouse: ALTER ... column type change generates ANSI "ALTER COLUMN ... SET DATA TYPE" instead of "MODIFY COLUMN"

**Before you file an issue**
- read dialect: clickhouse (and postgres in repro A)
- write dialect: clickhouse
- Confirmed the issue still exists on the latest release (30.11.0) and main: the ClickHouse Generator does not override altercolumn_sql, so it falls back to the base implementation using ALTER_SET_TYPE = "SET DATA TYPE".

**Fully reproducible code snippet**
```python
import sqlglot
from sqlglot import exp

# A) Transpiling a column type change into ClickHouse
print(sqlglot.transpile("ALTER TABLE t ALTER COLUMN c TYPE BIGINT", read="postgres", write="clickhouse")[0])
# Actual:   ALTER TABLE t ALTER COLUMN c SET DATA TYPE Nullable(Int64)
# Expected: ALTER TABLE t MODIFY COLUMN c Int64

# B) Building the AST directly (e.g. as a tool like SQLMesh does) and rendering ClickHouse
print(
    exp.Alter(
        this=exp.to_table("t"),
        kind="TABLE",
        actions=[
            exp.AlterColumn(
                this=exp.column("c"),
                dtype=exp.DataType.build("Nullable(Int32)", dialect="clickhouse"),
            )
        ],
    ).sql(dialect="clickhouse")
)
# Actual:   ALTER TABLE t ALTER COLUMN c SET DATA TYPE Nullable(Int32)
# Expected: ALTER TABLE t MODIFY COLUMN c Nullable(Int32)
```

**Official Documentation**

ClickHouse changes a column's type with `ALTER TABLE ... MODIFY COLUMN c <type>`. The ClickHouse generator didn't override `altercolumn_sql`, so it fell back to the ANSI `ALTER COLUMN c SET DATA TYPE <type>`, which ClickHouse doesn't accept. This overrides `altercolumn_sql` to emit `MODIFY COLUMN` for type changes and delegates the other alter-column forms to the base generator.

Fixes #7793.
