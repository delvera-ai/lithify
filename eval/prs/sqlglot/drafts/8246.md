In sqlglot (parser, optimizer dialect): Support starrocks GENERATE_SERIES parse and qualify.

## Issue #8244: qualify_columns fails on StarRocks TABLE() (table-valued functions) — Column could not be resolved

## Description

When using `lineage()` with `validate_qualify_columns=True` on SQL containing StarRocks table-valued functions (TVF) like `TABLE(generate_series(...))`, `qualify_columns` raises `OptimizeError: Column 'xxx' could not be resolved`.

The root cause is that `TABLE(func(...))` is parsed as `Table(this=Anonymous('TABLE', [...]))`, resulting in an empty `Table.name`. This means:
1. No schema can be registered for it in `MappingSchema` (no valid table name to use as key)
2. `qualify_columns` recursively validates column sources and fails when it reaches columns from the TVF

## Reproduce

```python
from sqlglot import parse, Dialect, exp
from sqlglot.dialects.dialect import NormalizationStrategy
from sqlglot.lineage import lineage
from sqlglot.schema import MappingSchema

sql = """
WITH t AS (
  SELECT p.user_id, gs.n AS to_deposit_days
  FROM tbl1 p
  CROSS JOIN (
    SELECT generate_series AS n FROM TABLE(generate_series(0, 8000))
  ) gs
),
t2 AS (
  SELECT t.* FROM t
)
SELECT user_id, to_deposit_days FROM t2
"""

dialect = Dialect.get_or_raise('starrocks')
dialect.normalization_strategy = NormalizationStrategy.CASE_INSENSITIVE
expression = parse(sql, read='starrocks')[0]

schema = MappingSchema(dialect=dialect)
schema.add_table("default.tbl1", column_mapping={"user_id": "BIGINT"}, match_depth=False)

# This raises: OptimizeError: Column 'generate_series' could not be resolved
lineage(column=None, sql=expression, schema=schema, dialect=dialect,
        expand_stars=True, validate_qualify_columns=True)
Expected Behavior
TABLE(func(...)) should be recognized as a table-valued function source. Columns referencing TVF output should either:

Be resolved against the TVF's known output schema (e.g., generate_series outputs a column named generate_series), or
Be skipped during validation (not treated as unresolvable external columns)
Workaround
Setting validate_qualify_columns=False allows lineage to complete, but loses strict column validation for the entire query.

Environment
sqlglot version: 30.12.0
Dialect: starrocks

Fixes #8244
