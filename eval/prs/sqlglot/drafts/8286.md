In sqlglot (mysql dialect): Parse BINARY column attribute as a column constraint.

Implements the parser support suggested in #8224 ("You should treat it as a constraint").

MySQL accepts `BINARY` as a column attribute after a string type in `CREATE TABLE` (shorthand for the binary collation of the column charset; deprecated since MySQL 8.0.17 but still common in older dumps). The MySQL parser has no `CONSTRAINT_PARSERS` entry for it, so parsing fails right after the data type:

```python
>>> sqlglot.parse_one("CREATE TABLE t (c VARCHAR(16) BINARY)", read="mysql")
sqlglot.errors.ParseError: Expecting ). Line 1, Col: 36.
```

After:

```python
>>> sqlglot.parse_one("CREATE TABLE t (c VARCHAR(16) BINARY)", read="mysql").sql(dialect="mysql")
'CREATE TABLE t (c VARCHAR(16) BINARY)'
```

The change mirrors the existing `ZEROFILL`/`INVISIBLE` attribute handling: a `BinaryColumnConstraint` expression, a MySQL-only `CONSTRAINT_PARSERS` entry, and a base generator transform. `BINARY` as a data type (`c BINARY(16)`) and as the unary cast operator (`SELECT BINARY x`) are unaffected.

Disclosure: implemented with Claude; I reviewed each line and reproduced the behavior locally.
