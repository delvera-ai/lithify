In sqlglot (sqlite dialect): Preserve explicit end bound in RANGE CURRENT ROW window frames.

## Issue #8209: SQLite: RANGE window frames starting at CURRENT ROW silently lose their end bound

**Fully reproducible code snippet**

```python
import sqlite3, sqlglot

sql = "SELECT id, SUM(amt) OVER (ORDER BY id RANGE BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING) AS remaining FROM t"
out = sqlglot.transpile(sql, read="sqlite", write="sqlite")[0]
print(out)  # SELECT id, SUM(amt) OVER (ORDER BY id RANGE CURRENT ROW) AS remaining FROM t

con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE t (id INTEGER, amt INTEGER)")
con.executemany("INSERT INTO t VALUES (?, ?)", [(1, 10), (2, 20), (3, 30)])
print(con.execute(sql).fetchall())  # [(1, 60), (2, 50), (3, 30)]
print(con.execute(out).fetchall())  # [(1, 10), (2, 20), (3, 30)]  <- silently different
```

`RANGE BETWEEN CURRENT ROW AND 1 FOLLOWING` is truncated the same way, and every read dialect is affected when `write="sqlite"` (duckdb/postgres/snowflake all produce `RANGE CURRENT ROW` here). `ROWS` frames and `RANGE` frames with other start bounds are generated correctly. Verified on main (a580417) with SQLite 3.53.

The parser captures the full frame (`end='UNBOUNDED'`, `end_side='FOLLOWING'`), so the expected output is to keep the `BETWEEN` form whenever `end` is set — SQLite has supported it since 3.28 — and only use the short form for frames that genuinely end at the current row.

**Official Documentation**

https://www.sqlite.org/windowfunctions.html#frame_specifications — a frame specification with no ending boundary defaults to ending at the current row.
