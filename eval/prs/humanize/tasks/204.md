Bug: some i18n tests fail intermittently when the test order is randomised (e.g. with pytest-randomly), with "Humanize cannot determine the default location of the 'locale' folder". The way `humanize.i18n` locates its bundled `locale` directory is fragile.

Make the default locale path lookup robust by resolving it through the module's import spec / package resources (`importlib`) rather than the module's `__file__` attribute. If the module spec is missing or unusable, the same "cannot determine the default location" exception should still be raised. (Constraint stated by the task author: the lookup must be based on the module spec, since that is what the maintainers asked for.)
