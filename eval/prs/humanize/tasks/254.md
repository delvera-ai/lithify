Bug: `humanize.precisedelta()` rounds incorrectly at the minimum unit when a `format` like `"%d"` is used, which gives output such as:

```python
>>> precisedelta(timedelta(days=31), minimum_unit="days", format="%d")
'1 month and 0 days'     # expected '1 month'
>>> precisedelta(timedelta(days=92), minimum_unit="days", format="%d")
'3 month and 0 days'     # expected '3 months'
```

Pluralisation and the displayed value of the minimum unit should agree with the number as it is actually formatted (`%d` truncates, `%.0f` rounds), zero-valued trailing units should not be shown, and carrying into the next unit should be handled. The same applies at seconds precision when microseconds are present.
