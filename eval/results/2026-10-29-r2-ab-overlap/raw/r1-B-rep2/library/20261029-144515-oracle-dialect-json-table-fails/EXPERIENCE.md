# 20261029-144515-oracle-dialect-json-table-fails

**Task:** Oracle dialect: `JSON_TABLE` fails to parse when the input expression carries `FORMAT JSON` (e.g. `JSON_TABLE(doc FORMAT JSON, '$.items[*]' COLUMNS (...))`). Support `FORMAT JSON` there so it parses and round-trips.

## Transferable lesson

- **cue:** A bug report says a clause of a SQL construct fails to parse (here, JSON_TABLE with FORMAT JSON). The reported form already parses. Probing sibling variants of that same clause finds one that errors with the report's message shape, and the repo has no local grammar reference for that variant.
- **lesson:** In skills/parse-failure-triage step 3, keep the bound that an accepted clause needs its parent construct, but do not make the fix conditional on verifying the grammar. State that an in-scope ERR matching the report's wording is fixed in the owning parser, and that the grammar source goes in the final message as a disclosure. The conditional wording in comp-1 was read as a veto and produced no fix, the unconditional wording in inv-1 produced the fix, and base-1 with no skill also produced no fix.
- **evidence:** skills/parse-failure-triage (inv-1 vs comp-1 rows); the skill-free base-1 outcome; the verdict on skills/parse-failure-triage (inv-1) is helped.
- **confidence:** low-medium. Each candidate has one rollout, so a single fix could be sampling variance. The fix also accepted ENCODING without FORMAT JSON, and the record does not establish whether Oracle's grammar allows that. Gates were not sensitive to the fix, so the win rests on the trajectory and the deliverable alone.
