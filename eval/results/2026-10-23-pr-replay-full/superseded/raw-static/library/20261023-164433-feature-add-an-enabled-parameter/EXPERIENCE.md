# 20261023-164433-feature-add-an-enabled-parameter

**Task:** Feature: add an `enabled` parameter (default `True`) to `Retrying`, `AsyncRetrying` and the `@retry` decorator. With `enabled=False` the decorated function is called directly, exactly once, with no retry logic, and any exception it raises propagates unchanged. This is useful during development and testing.

## Transferable lesson

- **cue:** A tenacity feature adds a new configuration knob to `Retrying`/`AsyncRetrying`/`@retry`, or mirrors an attribute that an earlier commit already threaded through the class family. The work is spread over several sites (constructor, `copy()`, subclass re-declarations, decorator overloads, `__repr__`), and agents reliably find the call paths but drop the passive sites.
- **lesson:** In `skills/tenacity-change-contract`, keep a per-site checklist taken from the precedent commit (the `name`/#597 sites, including `__repr__`), triggered from the skill's description. Phrase the execution-path part as a list of where the knob could matter, not as an order to change every loop: the same "reach every execution path" sentence led one rollout to add iterator-path machinery the task never asked for.
- **evidence:** Row 1 (`skills/tenacity-change-contract` CONTRACT section): `__repr__` was present in dom-1 and comp-1 and absent in base-1 and inv-1, and selection cited it. The iterator scope diverged between dom-1 and comp-1 under identical text.
- **confidence:** low. There is one rollout per harness, only the passive `__repr__` site contrasts, and the scoping caveat rests on two rollouts that diverged under the same text.
