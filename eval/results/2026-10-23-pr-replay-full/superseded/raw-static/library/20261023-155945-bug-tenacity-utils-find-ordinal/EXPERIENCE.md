# 20261023-155945-bug-tenacity-utils-find-ordinal

**Task:** Bug: `tenacity._utils.find_ordinal` (used for "1st attempt"-style wording in log messages) returns the wrong suffix for numbers greater than 20 that end in 11, 12 or 13: for 111, 112 and 113 it gives "st", "nd" and "rd", so messages read "111st", "112nd", "113rd". They should get "th"; all other numbers keep their current suffixes.

## Transferable lesson

- **cue:** The task fixes or changes user-visible behaviour in tenacity (log or error text, defaults, API), and the task text only asks for the code fix. The harness has nothing that tells the agent about the repo's ship-with-fix artifacts (reno notes in `releasenotes/notes/`).
- **lesson:** Keep the on-demand skill `skills/tenacity-change-contract` and its one-line pointer in `memory.md`. The skill spells out the reno note (file name pattern, `fixes:`/`features:` YAML, no edits to `changelog.rst`) and the test-module map. Without it, rollouts deliver a correct code-only fix and leave out the release note. Add new repo-convention facts to this skill rather than to always-on `system.md`.
- **evidence:** Row skills/tenacity-change-contract (dom-1 and comp-1 loaded it and added reno notes; base-1 and inv-1 did not). Row memory.md (bundled with the skill, so confounded).
- **confidence:** medium. The contrast is clean (2 of 2 with the skill added a note, 0 of 2 without), and the release note decided selection. But there is one rollout per candidate, and it is unknown whether the skill would load without the memory.md pointer.
