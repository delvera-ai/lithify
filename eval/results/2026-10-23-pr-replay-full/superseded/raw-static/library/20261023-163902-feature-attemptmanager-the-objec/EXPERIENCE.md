# 20261023-163902-feature-attemptmanager-the-objec

**Task:** Feature: `AttemptManager` (the object yielded by `for attempt in Retrying(...)` / `async for attempt in AsyncRetrying(...)`) should also support the async context-manager protocol, so `async with attempt:` works inside `async for` loops, behaving exactly like `with attempt:`.

## Transferable lesson

- **cue:** A tenacity feature task describes only the runtime behaviour (here, "`async with attempt:` should work like `with attempt:`") and does not mention docs or examples. A harness edit proposes adding another file that features "must" touch to the contract skill, citing that past feature commits touched it (e.g. `doc/source/index.rst`).
- **lesson:** In `skills/tenacity-change-contract/SKILL.md`, keep the required artifact list at code + reno note + regression test. Do not add `doc/source/index.rst` (or any similar convention mined from commit history) as a required file for features. If it is mentioned at all, make it conditional ("only if the task asks for docs or changes a documented example"), and leave it out of the "Confirm they agree" required-diff list and the skill `description`. Without such a rule, rollouts deliver the smaller change that was preferred. With it, they reliably add out-of-scope doc blocks they cannot verify.
- **evidence:** The `skills/tenacity-change-contract` docs row (dom-1 and comp-1 both added `index.rst` `testcode` examples; neither base-1 nor inv-1 did; selection ranked those two last for that reason). The mirror-tests row is consistent with the lesson but confounded.
- **confidence:** low. Each candidate has a single rollout, and the docs rule always came bundled with the mirror-tests rule. The judgment that the doc edit was unwanted comes from one selection pass, not from gates, which all four rollouts passed.
