# 20261023-161759-regression-since-8-4-2-composing

**Task:** Regression since 8.4.2: composing a `retry_base` instance with a plain function using `|` or `&` (e.g. `retry_if_exception_type(IOError) | my_predicate`, in either order) raises an exception instead of producing a `retry_any`/`retry_all`. Composition with plain callables worked in 8.3.0 and should work again for both sync and async retry strategies; type annotations should accept plain callables too.

## Transferable lesson

- **cue:** A tenacity regression task lists several variants of the bug (operand orders, `|` and `&`, sync and async strategies, decorator vs `Retrying`) and asks that all of them work. Some variants may already work on HEAD because they take a different code path, for example `async_retry_base` overrides of the operators that `retry_base` delegates.
- **lesson:** In `skills/tenacity-change-contract/SKILL.md`, give the agent steps to follow, not only facts about the code paths. Before any edit, run one snippet on unmodified HEAD that tries each named variant in its own try/except and prints which ones raise. Then require that every variant named in the task is exercised by a test, and that each test function contains at least one case that fails on HEAD (so fails_on_base still passes). Don't tell the agent to build tests only from the cases that fail, because that drops the working orders and async coverage from the tests and the release note.
- **evidence:** The "Reproduce every variant" row (helped): inv-1 and comp-1 got fails_on_base GOOD on the first try. base-1 and dom-1, the latter despite dom-1's descriptive async-path warning (dispatch-facts row, confounded), wrote async-only tests that passed on HEAD and had to be rewritten. The "Build tests only from cases that fail" row (confounded): comp-1 cited that clause to drop reverse-order and async tests, and selection named those gaps as why it lost. inv-1, under the same clause, kept full coverage.
- **confidence:** medium. Two rollouts with the reproduction step and two without split cleanly on the first-try fails_on_base result. The coverage-narrowing part rests on one rollout (comp-1), which echoed the clause verbatim, against inv-1, which did not narrow. That makes the "cover every named variant" half plausible but not established.
