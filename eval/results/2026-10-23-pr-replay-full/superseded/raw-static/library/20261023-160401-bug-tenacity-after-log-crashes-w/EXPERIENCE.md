# 20261023-160401-bug-tenacity-after-log-crashes-w

**Task:** Bug: `tenacity.after_log` crashes with `TypeError` when `retry_state.seconds_since_start` is `None` (it is `None` when the outcome timestamp has not been set). The log message should still be emitted, showing "?" in place of the elapsed seconds.

## Transferable lesson

- **cue:** The tenacity-change-contract skill asks the agent to verify something, such as "test fails on the old code", but gives no command for it. The only obvious way to do it is a state-changing git round-trip (stash/apply/drop, or hand-reverting the fix) on the working tree that holds the deliverable.
- **lesson:** Ship the check as a deterministic, read-only script under `skills/tenacity-change-contract/scripts/` (temp copy of HEAD plus the working-tree tests, with clear exit codes and a "report not verified on exit 2" rule). Add an explicit invocation line in `skills/tenacity-change-contract/SKILL.md`'s DONE checklist, where the requirement is stated. Don't leave the agent with prose that just says "verify it".
- **evidence:** The `skills/tenacity-change-contract/scripts/fails_on_base.py` row and the inseparable DONE pointer in `skills/tenacity-change-contract/SKILL.md`. inv-1 and comp-1 each verified in one call with the correct TypeError. base-1's improvised stash broke and needed two recovery calls. dom-1 skipped verification entirely.
- **confidence:** medium. The same contrast shows up in two separate candidate rollouts against two without the script, but there is only one rollout per harness. It improved the process and the backing for the final message, not the quality of the deliverable: all four passed gates, and the adopted deliverable (dom-1) did not have the script.
