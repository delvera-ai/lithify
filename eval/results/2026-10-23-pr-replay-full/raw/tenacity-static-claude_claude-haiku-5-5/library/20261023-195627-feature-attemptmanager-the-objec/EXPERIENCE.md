**Task:** Feature: `AttemptManager` (the object yielded by `for attempt in Retrying(...)` / `async for attempt in AsyncRetrying(...)`) should also support the async context-manager protocol, so `async with attempt:` works inside `async for` loops, behaving exactly like `with attempt:`.

## Transferable lesson

- **cue:** A tenacity feature task that adds API or a new way to use existing API (a new protocol on an existing object, a new keyword, async/trio variant) where the user docs show the existing usage form without naming the class, so a grep for the class or method name over doc/ finds nothing and the change ships code+test+reno but no docs.
- **lesson:** In the on-demand skill `skills/tenacity-change-contract`, list user docs as a required touch for features: edit `doc/source/index.rst` (README.rst symlinks to it) next to the existing example. Locate the section by grepping the existing usage snippet (e.g. `with attempt:`), not the class name. Write the example as a `.. testcode::` block that defines but doesn't run async functions. Name it in the skill description so it loads for the change. Keep it out of always-on system.md.

- **confidence:** medium. The contrast is clean and dom-1 isolates the edit, but each arm has one rollout per harness (two with §2a, two without) on a single task.
