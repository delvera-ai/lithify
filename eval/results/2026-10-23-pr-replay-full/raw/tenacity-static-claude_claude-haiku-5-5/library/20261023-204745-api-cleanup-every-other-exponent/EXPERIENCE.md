# 20261023-204745-api-cleanup-every-other-exponent

**Task:** API cleanup: every other exponential wait class uses `multiplier`, but `wait_exponential_jitter` uses `initial`. Add a `multiplier` parameter (default 1) to `wait_exponential_jitter` with the same meaning, and deprecate `initial`: passing `initial` (by keyword or positionally) must still work but emit a `DeprecationWarning`, and passing both `initial` and `multiplier` must raise `ValueError`.

## Transferable lesson

- **cue:** A tenacity task renames, replaces or deprecates a constructor argument of a public strategy or class: "add X with the same meaning, deprecate Y, Y must still work but warn, passing both raises". The class stores each argument as a same-named public attribute.
- **lesson:** Give the agent an on-demand `skills/deprecate-parameter` skill, or a section in `skills/tenacity-change-contract`. It should require: keeping the old attribute readable as a read-only `@property` aliasing the new one, or naming its removal as a break; a call-form test matrix that includes "new name" and "no arguments" calls with no warning, asserted under `simplefilter("error")` because the pytest filter is `once`; and a check that the warning's filename is the caller's. Do not recommend `tenacity/__init__.py` helpers such as `_unset` for code in `wait.py`, because importing them is circular.
- **evidence:** skills/deprecate-parameter row (no-warning tests and stacklevel check appear only in the two rollouts that loaded it, inv-1 and comp-1; the old attribute was kept in inv-1 where base-1 dropped it). skills/tenacity-change-contract row (its attribute clause, tested alone in dom-1, also kept the property).
- **confidence:** medium. Two different components that share the attribute clause each turned base-1's dropped attribute into a kept property, and the no-warning tests line up exactly with which rollouts loaded the skill (2 vs 2). But each condition has only one rollout, and base-1 noticed the attribute issue itself, so a rerun could vary.
