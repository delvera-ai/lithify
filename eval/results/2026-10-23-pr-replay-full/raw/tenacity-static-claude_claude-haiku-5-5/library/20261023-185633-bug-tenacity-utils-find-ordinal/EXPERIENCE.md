# 20261023-185633-bug-tenacity-utils-find-ordinal

**Task:** Bug: `tenacity._utils.find_ordinal` (used for "1st attempt"-style wording in log messages) returns the wrong suffix for numbers greater than 20 that end in 11, 12 or 13: for 111, 112 and 113 it gives "st", "nd" and "rd", so messages read "111st", "112nd", "113rd". They should get "th"; all other numbers keep their current suffixes.

## Transferable lesson

- **cue:** A tenacity task that changes behaviour a library user can notice (a bug fix, changed log or message text, new API, dropped Python version) where the gate only runs pytest. Repo conventions such as a reno release note in `releasenotes/notes/` are not enforced by CI or the gate, so a harness that only says "make the smallest change and pass the checks" leaves them out.
- **lesson:** Write unenforced deliverable conventions into the on-demand skill `skills/tenacity-change-contract`, with the exact file path pattern, the YAML section key and the house entry style, and have it load for any user-visible change under `tenacity/`. Don't put them in always-on `system.md`. Keep the skill's lint-tooling advice to the known-working steps (throwaway `/tmp` venv, ruff on changed files only) so discovering the tooling doesn't take over the run.
- **evidence:** skills/tenacity-change-contract row. dom-1 changed only this skill and produced a reno note. comp-1 also carried it and also produced one. base-1 and inv-1 lacked it and produced none. Selection picked between deliverables on exactly that note.
- **confidence:** medium. dom-1 isolates the skill and the split is 2 of 2 with the skill against 0 of 2 without, but each harness has only one rollout and this was a single task.
