# 20261023-214407-bug-retry-if-exception-message-m

**Task:** Bug: `retry_if_exception_message(message="")` raises `TypeError` ("missing 1 required argument 'message' or 'match'"), even though an empty string is a valid message to match (e.g. `str(RuntimeError()) == ""`). An empty `message` (or empty `match`) must be accepted and matched correctly; passing neither or both must still raise `TypeError`. The same applies to `retry_if_not_exception_message`.

## Transferable lesson

- **cue:** A tenacity task in which the agent has to consult the large `tenacity-change-contract` skill (about 30 KB, many `## N.` sections) but needs only a few sections, typically §2 (reno note) and the docs/tests sections for a small user-visible fix. A whole-file read of a skill that size spills to persisted output and costs extra recovery calls.
- **lesson:** In `tool_guidance.md`, tell the agent how to read a large harness skill rather than only where it is: name the skill as oversized and prescribe `grep -n '^## ' <SKILL.md>` followed by `sed -n 'A,Bp'` of the relevant sections, in place of `cat`. Reword the existing "where skills live" bullet instead of adding a new always-on line.
- **evidence:** The `tool_guidance.md` row. base-1 ran `cat`, got the 30.9 KB persisted-output spill and needed three more calls (one with exit 1). inv-1 and comp-1 each ran one heading grep and one section `sed`, with no spill. The `scripts/check_changed.py` edits were inert in both candidate rollouts, so they do not confound this.
- **confidence:** medium. Two of two candidate rollouts followed the prescribed pattern and the one base rollout did not, but there is only one base sample. The gain is in steps and cost (89 s down to about 55 s, partly confounded by base-1's separate checker detour), not in deliverable quality, which was equivalent across all three.
