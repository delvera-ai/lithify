# 20261023-190230-bug-tenacity-after-log-crashes-w

**Task:** Bug: `tenacity.after_log` crashes with `TypeError` when `retry_state.seconds_since_start` is `None` (it is `None` when the outcome timestamp has not been set). The log message should still be emitted, showing "?" in place of the elapsed seconds.

## Transferable lesson

- **cue:** A tenacity bug fix where the reported failure (an exception or wrong log text) can be reproduced from a unit test built with the existing `tests/test_tenacity.make_retry_state` helper, the gate runs only pytest, and ruff, mypy and PyYAML can't run in the environment.
- **lesson:** Keep the red-before-green step in `system.md`: write the regression test, run it alone by node id against the unfixed code, and confirm it fails with the reported error before editing `tenacity/`. Don't add a `scripts/` checker that builds a /tmp venv to install lint tools; ensurepip aborts here. Put the "lint/types/YAML can't run, report them as not run" fact in `tool_guidance.md` instead.
- **evidence:** system.md row: 2 of 2 carriers ran the test red with the reported TypeError, 0 of 2 non-carriers did, the same split as the previous library entry 20261023-185633. scripts/check_changed.py row: exit 2 from ensurepip SIGABRT, no check ran, and the highest cost of the round.
- **confidence:** medium. The red-first split has now held across two tasks (4 of 4 carriers against 0 of 4 non-carriers), and only system.md asks for it. But each harness ran once per task, and the shipped fixes were the same either way, so the gain is in verification, not in the patch. The script verdict rests on a single rollout.
