# 20261023-203956-feature-wait-exponential-jitter

**Task:** Feature: `wait_exponential_jitter` should be consistent with `wait_exponential`: add a `min` parameter that sets a floor on the wait, and accept `datetime.timedelta` values for `max`, `jitter` and `min` (as well as numbers of seconds).

## Transferable lesson

- **cue:** A tenacity task asks for two or more separate additions to one API, where each can be missing on its own (a new keyword plus a newly accepted type for existing arguments, or several new options on one strategy). A single combined test would fail on whichever missing part it hits first.
- **lesson:** Keep the clause in `system.md` step 1 that asks for one regression test per requested part, each shown failing for its own reason before the fix. Make it say that a test using an existing argument with a new type must not also pass the new keyword, because then its red run proves only that the keyword is missing.
- **evidence:** The `system.md` row. inv-1 changed only `system.md` and wrote separate per-part tests from the start, each failing for its own reason. comp-1 did the same. base-1 had no such clause, used a combined test, and admitted the timedelta path was never shown failing. dom-1 reached a split only after a wasted red run, prompted by a narrower skill bullet.
- **confidence:** medium. inv-1 isolates the edit and comp-1 repeats the behaviour, but each arm has only one rollout. dom-1 shows a capable agent can sometimes reach the split without the clause.
