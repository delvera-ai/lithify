The `enabled=False` bug is fixed for the iterator form. `for attempt in Retrying(enabled=False)` and `async for attempt in AsyncRetrying(enabled=False)` now run the body once, and exceptions propagate unchanged. The full suite passes (164 passed, 1 skipped, exit 0). Nothing is committed.

**Root cause:** `enabled` was only checked in `wraps()`, so the decorator skipped retry logic but the iterator never looked at it. `AttemptManager.__exit__` also swallows every exception, which is what drove the retry loop.

**Changes:**
- `tenacity/__init__.py`:
  - `AttemptManager.__exit__` returns `None` when the owning retry object is disabled, so the exception propagates.
  - `BaseRetrying.__iter__` yields one attempt and returns when disabled.
- `tenacity/asyncio/__init__.py`: `__aiter__` and `__anext__` do the same. `__aiter__` skips `begin()` when disabled, and `__anext__` yields once, then stops.
- Tests (`tests/test_tenacity.py`, `tests/test_asyncio.py`): two sync and two async tests covering a failing body and a successful body.
- Docs: one sentence in the "Disabling Retries" section of `doc/source/index.rst`.
- Reno note: `releasenotes/notes/fix-enabled-false-iterator-3c9a2e7f14b08d61.yaml` as a `fixes:` entry.

**Verification:**
- The two failing-body tests failed on the unfixed code with `RetryError` after 3 attempts, the reported symptom. After the fix, all `TestEnabled` and `TestAsyncEnabled` tests pass.
- `check_changed.py`: exit 0, 0 problems. ruff and mypy were not run; they are unavailable in this environment.

**Choices and limits:**
- The disabled iterator path skips `begin()` and `before`/`after` callbacks, the same as the decorator's raw-call path. `statistics` stays unset for that run.
- Outside this change: `Retrying(enabled=False)(fn)` (direct call) and `retry_with`-less direct `__call__` still ignore `enabled`. This matches the original code and is not part of the reported bug. Say if you want it covered too.
