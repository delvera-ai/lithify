final message:
Composing a `retry_base` strategy with a plain callable via `|` or `&` works again, in either operand order, for sync and async strategies. The full suite passes (139 passed, 1 skipped) and `check_changed.py` reports 0 problems.

**Cause:** `retry_base.__or__` and `__and__` always called `other.__ror__(self)` / `other.__rand__(self)`. A plain function has neither method, so `retry_if_exception_type(IOError) | my_predicate` raised `AttributeError`. I did not bisect against 8.3.0 to confirm that is the exact 8.4.2 change, but the failing traces match this path.

**Changes:**
- `tenacity/retry.py`: the operators delegate only when the other operand is a `retry_base`. A plain callable gets `retry_any(self, other)` / `retry_all(self, other)` directly, keeping operand order. The operator and `retry_any`/`retry_all` annotations now use `RetryBaseT`, which already includes plain callables.
- `tenacity/asyncio/retry.py`: the async operators already handled plain callables at runtime, so only the annotations changed. They now accept `SyncRetryBaseT | RetryBaseT`, with the sync alias imported under `TYPE_CHECKING`, as `asyncio/__init__.py` does.
- Tests: `test_retry_or_plain_callable` and `test_retry_and_plain_callable` in `TestRetryConditions`, and `test_retry_with_sync_strategy_or_plain_callable` in `TestContextManager`. All three failed on the unfixed code with the reported `AttributeError` and pass now. The existing async composition tests (`_or`, `_ror`, `_and`, `_rand`) still pass.
- Release note: `releasenotes/notes/fix-compose-plain-callable-49cb3dad0f5eb33e.yaml`, a `fixes:` entry.
