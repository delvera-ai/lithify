# trajectory inv-1

final message:
`Retrying` objects and the built-in retry, stop, and wait strategies now pickle, including a `Retrying` that has already run and holds statistics. A `Retrying` passed to `multiprocessing.Pool.map` now works. The changes are not committed.

**Root causes**
- `BaseRetrying` kept its per-thread state in a `threading.local`, which can't be pickled.
- Several built-in predicates were lambdas or nested functions. The default `retry_if_exception_type()` is one, so even a plain `Retrying()` failed to pickle.

**Changes**
- `tenacity/__init__.py`: `BaseRetrying.__getstate__`/`__setstate__` drop the `threading.local` and rebuild it on restore. They carry the calling thread's statistics across. The per-run iteration state is rebuilt lazily.
- `tenacity/retry.py`: the lambdas and nested functions in `retry_if_exception_type`, `retry_if_not_exception_type`, `retry_unless_exception_type`, `retry_if_exception_message`, and `retry_if_not_exception_message` are replaced by module-level functions bound with `functools.partial`. Behaviour is unchanged.
- `tests/test_tenacity.py`: new `TestPickle` class covering a fresh and a used `Retrying`, `@retry`-decorated functions, and the strategy classes. It also checks that message predicates behave the same after a round trip.
- `releasenotes/notes/make-retrying-picklable-c13ae07c6ccbefc0.yaml`: a `fixes:` note, as the change contract requires.

**Verification**
- Before the fix, the new tests failed with `Can't get local object 'retry_if_exception_type.__init__.<locals>.<lambda>'`.
- Scratch `Pool.map` script (outside the repo): before the fix it crashed when a `Retrying` was passed to the workers. After the fix it prints `retrying: [2, 4, 6]`. The decorated-function case already worked, because pickle references the function by name.
- Full suite via `run_tests.py`: `exit=0`, 152 passed, 1 skipped. The skip is `test_trio_basic`, because trio isn't installed here.
- `check_changed.py`: exit 0, 0 problems.
- ruff and mypy were not run; the environment doesn't have them.

**Limits**
- `stop_when_event_set` still can't be pickled, because it holds a `threading.Event`. The reno note says so.
- User-supplied lambdas or closures passed as predicates or callbacks still can't be pickled. Use module-level functions for those.
- `AsyncRetrying` pickles and runs after a round trip. I checked this ad hoc and did not add a test to `test_asyncio.py`.
