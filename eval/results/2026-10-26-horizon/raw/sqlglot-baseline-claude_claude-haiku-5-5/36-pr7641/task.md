DuckDB (or any source where NULLs sort last) → MySQL: MySQL has no `NULLS FIRST/LAST`, so `ORDER BY` is simulated as `ORDER BY CASE WHEN <col> IS NULL THEN 1 ELSE 0 END, <col>`. The simulated `CASE` copies the raw expression, often a bare column name. In a multi-table `FROM` where that name exists in several tables, MySQL then fails with `Column '<name>' in order clause is ambiguous`. When the `ORDER BY` expression refers to a qualified column, or a projection alias, the simulation must keep the column reference unambiguous (e.g. qualified the same way as the `ORDER BY` reference).
