# 20261023-124909-add-parse-age-value-to-app-users

**Task:** Add `parse_age(value)` to app/users.py. It accepts an int, or a string of decimal digits with optional surrounding whitespace, and returns the age as an int. Valid ages are 0 to 150 inclusive. Anything else (other types, booleans, non-digit strings, negative numbers, ages over 150) must be rejected with `ValidationError`.

## Transferable lesson

- **cue:** You are adding a new function to a module in this repo (for example a new `parse_*` validator in `app/`). The nearest sibling functions follow an older pattern, while a shared helper module in the same package (such as `app/audit.py`) states a policy in its docstring that the siblings do not follow, typically a side effect on the reject or error path. The agent's own tests pass whether or not that side effect happens, so only reading the helper reveals it.
- **lesson:** Add an always-on rule to `system.md`: before writing a new function, open the package's shared helper modules (audit, logging, errors) as well as the siblings, because a file listing is not a read; where a helper's docstring states a policy, follow it over older sibling code. When the policy is already known, also state it as a one-line fact in `memory.md` that names the helper and marks the legacy siblings as not-to-copy. A full skill plus checker script is not needed for this.
- **evidence:** system.md row (inv-1 read `audit.py` because of the rule and passed, while base-1 listed but never opened it and failed 9/14 on "no audit record"); memory.md and skills/input-validation rows (dom-1 and comp-1, which pointed at the policy by a different route, also passed); check_audit.py row (no observed effect).
- **confidence:** medium. The contrast is consistent: the only harness with nothing pointing at the helper failed, and three differently built harnesses that did point there all passed, and inv-1 isolates that pointer within its own changes. But each harness had only one rollout, and the system.md and memory.md routes were never tested apart, so which route works better is unproven.
