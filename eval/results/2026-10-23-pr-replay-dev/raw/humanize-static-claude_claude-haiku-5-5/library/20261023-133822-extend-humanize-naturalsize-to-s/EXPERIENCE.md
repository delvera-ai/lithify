# 20261023-133822-extend-humanize-naturalsize-to-s

**Task:** Extend `humanize.naturalsize()` to support the new SI prefixes ronna (R, 10^27) and quetta (Q, 10^30) for decimal sizes, and their binary counterparts (RiB, QiB), as well as the GNU-style single-letter suffixes (R, Q). Values larger than the yottabyte range should now be expressed in RB/QB (or RiB/QiB, R/Q) instead of very large YB numbers.

## Transferable lesson

- **cue:** A task in this repo adds entries to an ordered lookup table that drives a formatting function, such as size suffixes in `filesize.py` or the prefix string in `number.metric`. Adding a unit moves the overflow cutoff and the boundaries that existing parametrize rows and docstring examples were written against.
- **lesson:** Add a `skills/<module>-units` skill for that module (`skills/humanize-filesize-units` is the template). It should name the single table and its parallel entries, and say that new entries are appended rather than changing the loop. It should list each place that must stay in step: the table, the docstring `pycon` examples (checked with an explicit `--doctest-modules` run), `README.md`, and the one parametrize table. Most importantly, it should ask for new rows per mode at the exact boundary, a value just inside it, and a value past the new top unit, computed by running the code before writing expectations. Don't spend harness edits on the edited-existing-tests gate for such tasks: the task makes those edits unavoidable. Reporting rules in `system.md` left that result unchanged.
- **evidence:** The `skills/humanize-filesize-units` row was helped. Both carriers navigated directly, covered the boundary, just-inside and past-the-top cases in every mode, and uncovered the float rounding bug. The `system.md` row had no observed effect on the gate, which failed the same way in all four rollouts.
- **confidence:** medium. The coverage pattern matches the skill's text and appears in both carriers and in neither non-carrier. But there is only one rollout per candidate, `memory.md` was changed alongside it in both, and no gate or selection result tells the deliverables apart.
