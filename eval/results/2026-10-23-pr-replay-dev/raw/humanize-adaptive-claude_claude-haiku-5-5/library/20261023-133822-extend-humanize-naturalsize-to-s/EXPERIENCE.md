# 20261023-133822-extend-humanize-naturalsize-to-s

**Task:** Extend `humanize.naturalsize()` to support the new SI prefixes ronna (R, 10^27) and quetta (Q, 10^30) for decimal sizes, and their binary counterparts (RiB, QiB), as well as the GNU-style single-letter suffixes (R, Q). Values larger than the yottabyte range should now be expressed in RB/QB (or RiB/QiB, R/Q) instead of very large YB numbers.

## Transferable lesson

- **cue:** The task in this repository changes a public function's output for inputs that existing parametrized test rows already assert. Example: extending a unit or suffix table so values that used to overflow into the old top unit now format differently. The literal old expected strings stay in the test file, and the gate checks both that the suite passes and that no pre-existing test line was changed.
- **lesson:** Leave the unconditional "never edit existing tests" rule in guardrails.md as it is. Don't add a "the task supersedes this assertion" exception, and don't add a "done means exit 0" rule to system.md. Both turn the failure into an edited-existing-tests gate failure instead of fixing it. Put the domain facts in a skills/<area> skill instead (which rows the change will break, new cases go in new rows or a new function with the negation check, inputs off exact float boundaries, doctests need a separate run), and have the agent report each conflicting row as `input: old -> new`.
- **evidence:** guardrails.md row (hurt: 4/4 rollouts with the exception edited pinned rows and failed edited-existing-tests; 4/4 without it left them alone); skills/humanize-filesize-units row (the comp versions kept the rule, predicted the conflicts and avoided the float boundary, though their "finish without asking" step was ignored)
- **confidence:** medium. The guardrail contrast holds across 8 rollouts and four different exception wordings. But no harness passed the gates, so this says what to avoid rather than what succeeds, and the skill-side benefits each come from one or two rollouts.
