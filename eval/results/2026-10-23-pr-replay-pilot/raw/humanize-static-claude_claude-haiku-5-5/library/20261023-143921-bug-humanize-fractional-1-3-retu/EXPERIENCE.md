# 20261023-143921-bug-humanize-fractional-1-3-retu

**Task:** Bug: `humanize.fractional(-1.3)` returns `"-1 -3/10"` with two minus signs; the same happens for any negative number whose absolute value is at least 1 (`fractional(-2.5)` gives `"-2 -1/2"`). Negative mixed numbers should be shown in the conventional form, e.g. `"-1 3/10"`.

## Transferable lesson

- **cue:** A humanize bug-fix task where the reported failing inputs sit beside neighbouring inputs that already give the right (or quirky) output, such as other signs, zero, or values that round to 0, and the agent adds regression cases to an existing `@pytest.mark.parametrize` list.
- **lesson:** Define "done" for a bug fix in always-on `system.md`, not in a module `skills/<name>`. Every new test case must fail on the unmodified code, and inputs that already behaved correctly go in the final message rather than in the test list. Also tell the agent to run the original code once, before editing, on every input it plans to add as a test, so it doesn't have to rebuild HEAD afterwards to check them.
- **evidence:** system.md row (inv-1 isolates it: only the two failing inputs added, against base-1/dom-1 pinning `-0.3`, `-1` and the `-0.0001 → "0/1"` quirk; comp-1 repeats it, at the cost of an extra HEAD check for an input it hadn't reproduced). skills/humanize-number-output row (dom-1's skill-borne test-layout guidance did not change which cases were added). This matches library entry 20261023-142110 (never-broken inputs judged off-target).
- **confidence:** medium. Each arm has one rollout, but the contrast holds in both directions (both rollouts with the edit pruned, both without it pinned unchanged inputs), the agent's own words in inv-1 and comp-1 show the mechanism, and a separate earlier task shows the same failure.
