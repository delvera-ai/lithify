# 20261023-145531-bug-humanize-naturalsize-can-sho

**Task:** Bug: `humanize.naturalsize()` can show the base value with the smaller suffix when rounding pushes a value up to the next unit:

```python
>>> naturalsize(999999)
'1000.0 kB'      # expected '1.0 MB'
>>> naturalsize(1024 ** 2 - 1, binary=True)
'1024.0 KiB'     # expected '1.0 MiB'
```

This happens at every decimal, binary and GNU boundary. After rounding, a value that reaches the base should be shown in the next unit. Values already at the largest suffix (QB/QiB) are unaffected.

## Transferable lesson

- **cue:** A humanize bug fix where the agent must show the reported output on the unmodified code and prove each new parametrize case changes output, and the harness has no ready-made old-vs-new tool. In that situation agents fall back on swapping `git show HEAD:<file>` over the working tree and copying the fix back in one shell chain.
- **lesson:** Keep `scripts/compare_outputs.py` in the harness (HEAD via `git archive` to a temp dir, a separate subprocess per side, a `C changed` summary line, exit 2 on setup failure). Point to it from always-on `tool_guidance.md` with the exact call form and an explicit ban on copying HEAD files over the tree, and say it is meant for both steps: before editing, to reproduce the bug (expect 0 changed, read the `old:` lines), and after editing, to confirm the new cases. The pointer alone was enough to get it adopted; no `system.md` wording was needed. Do not expect it to catch wrong test expectations; only the suite run does that.
- **evidence:** Rows scripts/compare_outputs.py (helped) and tool_guidance.md (confounded; its pointer line is the part with an observed effect).
- **confidence:** medium. The behaviour change replicated in 2 of 2 rollouts that had the edit, against base-1's tree-mutating swap, and it agrees with library entry 144514. But every rollout passed gates, so the gain is safer verification, not a better deliverable. The pointer and the script were always shipped together.
