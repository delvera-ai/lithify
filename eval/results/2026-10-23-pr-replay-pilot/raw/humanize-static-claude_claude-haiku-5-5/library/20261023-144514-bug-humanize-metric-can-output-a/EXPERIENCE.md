# 20261023-144514-bug-humanize-metric-can-output-a

**Task:** Bug: `humanize.metric()` can output a four-digit mantissa with a prefix that is too small, contradicting its docstring (the prefix is chosen so that non-significant zero digits are not needed):

```python
>>> metric(999.9, "V")
'1000 V'      # expected '1.00 kV'
>>> metric(999999, "V")
'1000 kV'     # expected '1.00 MV'
>>> metric(0.0009999, "V")
'1000 μV'     # expected '1.00 mV'
```

When rounding reaches 1000, the result should move to the next SI prefix. Values already at the largest prefix 

## Transferable lesson

- **cue:** A humanize bug fix that changes what a formatter returns, where the agent has to show the reported output on the unmodified code and confirm each new parametrize case changes (or sweep many inputs for unintended changes). This is the point where agents start rebuilding HEAD by hand: loading two copies of the package in one process, `git show` into /tmp, or copying HEAD files over the working tree.
- **lesson:** Ship the old-vs-new comparison as a harness script (`scripts/compare_outputs.py`: HEAD via `git archive` into a temp dir, each side in its own subprocess, checks the import path, ends with an `N expressions, C changed` line, exit 2 on setup failure). Point to it from `tool_guidance.md` with the "don't write your own: a shared `sys.modules` silently reports no change" warning, plus the "no `-I`" note. Don't rely on `system.md` wording alone to get this verification done correctly.
- **evidence:** scripts/compare_outputs.py (helped: inv-1/comp-1 got correct counts in one call each, while base-1 got "changed: 0" and then 50 false mismatches over four calls, and dom-1 skipped the comparison), tool_guidance.md (helped: `-I` avoided 2/2 with it, hit 2/2 without it, and it is how the agents found the script), system.md (confounded with the script).
- **confidence:** medium. Each harness had one rollout, and the gates didn't separate the candidates. The failure without the script is concrete and visible in the trajectories, and library entries 143921 and 142958 record the same HEAD-rebuild work going wrong in earlier rounds.
