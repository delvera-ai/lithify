# 20261023-150254-bug-humanize-fractional-produces

**Task:** Bug: `humanize.fractional()` produces degenerate output when the fractional part rounds to a whole number: `fractional(2.9999999)` returns `"2 1/1"` (expected `"3"`), `fractional(0.9999999)` returns `"1/1"` (expected `"1"`), and `fractional(0)` returns `"0/1"` (expected `"0"`). The result should read as a plain integer in these cases, including for negative inputs.

## Transferable lesson

- **cue:** A humanize fix or edit near the end of the task, where a lint or type tool that `pyproject.toml` or tox configures (ruff, mypy) is not installed in the project venv, and the harness names that tool or its rules without saying it is missing.
- **lesson:** In always-on `tool_guidance.md`, give one bullet to each configured-but-missing checker. Name it, give the exact failure (`No module named …`), say "don't run or install it", give a fallback that reads `[tool.ruff]` in `pyproject.toml` against the changed lines, and require the final message to say the check was not run. In any `skills/<name>` that lists that tool's rules (e.g. mypy `strict`, `RUF046`), point back to that bullet rather than naming the tool alone, because naming a tool without saying it is missing triggers a probe.
- **evidence:** tool_guidance.md row (base-1 probed ruff; inv-1 and comp-1, which had the bullet, did not, and inv-1 grepped `pyproject.toml` instead); skills/humanize-number-output row (dom-1's skill said nothing about mypy being missing, and dom-1 probed mypy).
- **confidence:** low. The contrast holds across two candidates, but each label had one rollout. The saving is one failed tool call plus a better-grounded disclosure. All four deliverables passed the gates, and their quality did not depend on these edits.
