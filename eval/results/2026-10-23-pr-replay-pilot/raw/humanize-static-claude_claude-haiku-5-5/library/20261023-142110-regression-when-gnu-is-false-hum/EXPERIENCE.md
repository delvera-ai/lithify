# 20261023-142110-regression-when-gnu-is-false-hum

**Task:** Regression: when `gnu` is False, `humanize.naturalsize(1.0)` or `naturalsize("1")` returns `"1.0 Byte"` instead of `"1 Byte"`, which was the return value until 4.12. Restore the previous output for float and numeric-string inputs that are below one kilobyte.

## Transferable lesson

- **cue:** Adding parametrized cases to a humanize test where the test body changes each case's arguments before asserting again (for example, `test_naturalsize` re-runs every case negated by prefixing `-` to non-int inputs), so a case that looks valid fails on the second assertion.
- **lesson:** Put the test function's argument-transformation contract in `memory.md` as one line saying which inputs are legal there. Do not put it inside a task-specific `skills/<name>` that also encodes the fix. A future task that adds cases to that test then avoids writing a case the retest will break, without loading a skill whose solution hints can pull its tests toward inputs that were never broken.
- **evidence:** memory.md row (inv-1 added only positive cases and passed on its first run; base-1 added `[-1.0]` and hit `'--1.0'`); skills/humanize-output-formatting row (the skill carried the same contract and also avoided the failure, but its two rollouts added `300.0`/`"300"` cases that selection judged off-target, and the deliverable chosen was base-1's)
- **confidence:** low. One base rollout shows the failure and three candidate rollouts avoid it. Each candidate changed more than one thing or carried the fact inside a larger skill, and no rollout repeats a configuration.
